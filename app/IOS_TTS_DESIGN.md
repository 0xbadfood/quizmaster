# iOS Local TTS Streaming Design

## Goal

StoryVault Talk should stream LLM text into on-device PocketTTS and play the
result without leaking stale audio between turns. Dart should not guess when
playback has finished. The iOS audio bridge must report when every scheduled
audio buffer for the active turn has actually been heard.

## Current Problem

The current local TTS flow estimates playback drain time from generated audio
duration and synthesis time. That estimate can be wrong when:

- PocketTTS emits audio progressively.
- Multiple text chunks are synthesized for one assistant turn.
- iOS buffers still contain scheduled audio after Dart thinks playback ended.
- A new ASR/LLM turn starts while old native buffers are still playing.
- The TTS progress callback returns cumulative samples instead of only new
  samples.

This can make previous text appear to leak into the next turn or make speech
sound duplicated/corrupted.

## Queue Model

Use two Dart-side queues and one native playback scheduler.

### 1. LLM Text Queue

The LLM text queue receives SSE deltas from the LLM router. It owns text
assembly only.

Responsibilities:

- Append incoming text deltas.
- Keep a rolling text buffer.
- Emit speakable text chunks using sentence boundaries, startup minimum
  characters, hard maximum characters, and fallback timeout.
- Attach `turnId`, `chunkId`, and text hash to each chunk.
- Mark the final chunk when the LLM stream ends.

It should not know whether native playback is drained.

### 2. TTS Audio Queue

The TTS queue consumes text chunks in order and calls local PocketTTS.

Responsibilities:

- Keep exactly one PocketTTS synthesis active at a time.
- Pass the active `turnId/sessionId` to every native playback write.
- Convert generated `Float32List` samples to PCM16.
- Detect whether Sherpa `onProgress(samples)` is cumulative or delta. If it is
  cumulative, forward only the new tail samples to native playback.
- Record diagnostics: text chunk, sample counts, TTFA, generated bytes, and
  synthesis time.

It should not decide that playback has finished just because synthesis has
finished.

### 3. Native Audio Output Queue

The native iOS bridge owns the truth about playback.

Responsibilities:

- Reject stale writes where `incomingSessionId != playbackSessionId`.
- Schedule PCM buffers into `AVAudioPlayerNode`.
- Count scheduled buffers/frames.
- Count buffers/frames after iOS reports they were played back.
- Resolve `finishPlaybackStream(sessionId)` only when all scheduled buffers for
  that session have completed playback.

The key iOS API is:

```swift
player.scheduleBuffer(
  buffer,
  completionCallbackType: .dataPlayedBack
) { _ in
  // This buffer has actually finished playing out.
}
```

`playerNode.isPlaying` is not sufficient because it does not prove the queued
buffers are empty.

## Session Isolation

Every assistant turn gets a monotonically increasing `sessionId`.

Rules:

- Dart increments the session when a new local TTS turn begins.
- Native playback stores the active session.
- Native drops writes, stops, and drain completions for stale sessions.
- Dart ignores TTS completions if the Dart generation no longer matches.

This prevents old work from mutating the current turn.

## Normal Turn Flow

```text
ASR transcript ready
  -> flush any interrupted previous playback
  -> start LLM stream
  -> LLM text queue emits chunks
  -> TTS queue synthesizes chunks
  -> native schedules audio buffers
  -> LLM final arrives
  -> TTS queue finishes all text chunks
  -> Dart calls finishPlaybackStream(sessionId)
  -> native waits for dataPlayedBack on every scheduled buffer
  -> native returns drained status
  -> Dart stops/clears playback
  -> mic opens for the next user turn
```

## Interruption Flow

```text
User interrupts / ASR starts a new turn
  -> Dart increments generation/session
  -> Dart clears LLM and TTS queues
  -> native stopPlayback invalidates the current session
  -> stale native completions are ignored
  -> stale Dart completions are ignored
```

Flush is therefore a turn-boundary or interruption action. It should not happen
after every sentence.

## Diagnostics

The diagnostics panel should expose enough state to debug the whole pipeline:

- Current `sessionId`
- Last queued TTS text
- Last spoken TTS text
- PocketTTS progress sample count
- PocketTTS forwarded sample count
- Native scheduled buffers/frames
- Native played buffers/frames
- Native pending buffers/frames
- Native drain wait time
- Whether a stale native write was dropped

## Implementation Notes

- Dart should continue to own text chunking and PocketTTS ordering.
- Swift should own playback drain truth.
- `_assistantPlaybackEndsAtMs` should not be used for local TTS completion once
  native drain tracking is available.
- `finishPlaybackStream(sessionId)` should mark the stream closed and return
  only after all buffers scheduled before and during the stream have played.
- If no audio buffers were scheduled, `finishPlaybackStream(sessionId)` can
  return immediately with a drained status.
